# Reproduction guide

All commands below run from `standalone/`. Build and test the C++ programs using
the [standalone instructions](../README.md), then install `requirements.txt`.
The tracked JSON files specify scientific parameters. Local data and executable
paths are configured separately, so the tracked protocol can be reviewed before
each run.

## Direct-statistics Sections 4.4–4.6

Obtain the Stanford VI-E source distribution and identify its root directory:

```text
Stanford-VI-E-master/
  Porosity/porosity.txt
  Facies/facies.dat
  Reservoir Simulation (Eclipse)/poro.inc
```

The three original inputs are required by preprocessing: the full porosity and
facies fields plus the Eclipse porosity reference. The code checks the fixed
shape, axis mapping, paired 2×2×2 reduction, and included co-location fixture.
A processed slice or an unrelated porosity file cannot replace this source
distribution. The [repository data directory](../../Paper-data/) documents
redistributed examples; external source data can remain outside the checkout.

Generate machine-local configurations by supplying that source directory:

```sh
python experiments/configure_paths.py --stanford-root "/path/to/Stanford-VI-E-master" --build-dir build --output output/local-config
```

On Windows, a path such as `"E:/datasets/Stanford-VI-E-master"` is also accepted.
`cmake` and `ctest` must be on `PATH`, or pass their full executable paths through
`--cmake` and `--ctest`. The helper validates inputs and native executables,
discovers `build/Release`, `build/bin`, or `build`, and writes a new configuration
directory without running an experiment. Use a new `--output` directory to
configure another environment.

The two acceptance modes and the formal mode share the same entrypoint:

```sh
python experiments/run_direct_sections_44_46.py --config-root output/local-config --mode smoke
python experiments/run_direct_sections_44_46.py --config-root output/local-config --mode analysis-smoke
python experiments/verify_direct_evidence.py output/direct_4_4_4_6_20261011/RUN_DIRECTORY --mode analysis-smoke --require-current-sources --require-time-budget
python experiments/run_direct_sections_44_46.py --config-root output/local-config --mode formal
python experiments/verify_direct_evidence.py output/direct_4_4_4_6_20261011/FORMAL_RUN_DIRECTORY --mode formal --require-time-budget
```

Replace the two directory placeholders with the timestamped directories printed
by the runner. Review the analysis-smoke time projection before starting the
formal matrix. The frozen protocol carries a six-hour formal time budget;
elapsed time depends on the machine and input workload. Acceptance modes are
implementation checks, and their results are not formal paper results.

Section 4.4 uses the production template CLI with exhaustive integer offsets and
directional surrogate comparisons. Section 4.5 compares uniform local maps
directly with channel facies. Section 4.6 compares spatial and attribute weights
on shared support, including parameter sensitivity. Formal runs produce 90
primary and 12 sensitivity C++ maps, reports, gate records and SHA-256 manifests.
The runner preprocesses inputs into its run directory and freezes the effective
configuration alongside the result.

## Conditional-window supplement

The final conditional-window analysis is generated by
`r1_5_incremental_value_20260924/conditional_high_order_window_analysis.py`.
It consumes the completed formal run, reconstructs the uniform 5×5×3 porosity
windows, and compares fifth- and sixth-order shape after conditioning on the
specified lower-order statistics. Ranks are fixed over each complete subvolume;
the spatial block bootstrap refits the rank regression within each resample.

```sh
python experiments/r1_5_incremental_value_20260924/conditional_high_order_window_analysis.py output/direct_4_4_4_6_20261011/FORMAL_RUN_DIRECTORY --output-dir output/conditional-window-analysis --bootstrap-replicates 2000 --seed 20261012
```

The input must retain `direct_analysis_values.csv`, the run-local porosity grids,
frozen configs, manifests, and the formal gate. Compact published result tables
alone are insufficient to reconstruct individual windows. The script validates
input hashes and writes all derivative evidence into a new directory outside
the formal run. The optional `--common-config` accepts only a byte-identical
copy of the run's frozen common protocol; normally omit it.

## Order 4–8 scalability

The [scalability benchmark](r1_11_scalability_20260909/README.md) compares Bell and
AVL on the fixed Stanford VI-E z=62 columnar grid. Supply that exact grid through
`--data`; the input SHA-256 is archived in each run. The benchmark accepts a
separate optional `--paper` path only as a read-only provenance hash.

```sh
python experiments/r1_11_scalability_20260909/run_benchmarks.py --build-dir build/Release --data "/path/to/exhaustive_image_z62.txt" --smoke --repeats 1 --warmups 0
python experiments/r1_11_scalability_20260909/run_benchmarks.py --build-dir build/Release --data "/path/to/exhaustive_image_z62.txt" --repeats 5 --warmups 1 --timeout 1800
```

Use `--build-dir build` with a single configuration generator. The input must
have the coordinates and extent required by the fixed case matrix. Peak process
memory measurement uses the Windows process API; portable correctness and
wall-clock timings can still be collected on other platforms, but Windows
peak-working-set values should be compared only with matching measurements.

Material generation consumes a completed evidence directory:

```sh
python experiments/r1_11_scalability_20260909/generate_paper_materials.py --run output/r1_11_scalability_20260909/RUN_DIRECTORY --out output/scalability-materials
```

The destination must be new. Each benchmark run retains generated configurations,
raw logs, coordinates, numerical comparisons, timing records, and source hashes.
